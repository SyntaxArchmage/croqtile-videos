# Product

## Register

brand

## Users

GPU kernel developers and CUDA programmers who write production-grade compute kernels: FlashAttention, Blockscale GEMM, custom fused ops. They work in C++/CUDA daily, understand memory hierarchies and warp-level primitives, and are frustrated by the boilerplate and fragility of current tooling. They evaluate new tools by reading code, not slides.

## Product Purpose

CroqTile is a high-performance GPU kernel DSL that eliminates the pain of writing, debugging, and optimizing compute kernels. These videos are launch/promotional content that demonstrates CroqTile's core value propositions: zero-cost abstractions, compile-time safety, dynamic shape support, and AI-native workflows. Success looks like a developer watching for 30 seconds and thinking "this understands my problem."

## Brand Personality

Precise, powerful, crafted. CroqTile speaks as a peer to expert GPU programmers, not a marketer. The tone is confident without being loud, technical without being dry. Every frame earns its place. The bilingual (Chinese/English) presentation reflects the global GPU development community.

## Anti-references

- Generic SaaS explainer videos with stock illustrations and bouncy transitions
- Corporate keynote slide decks with bullet points and gradient backgrounds
- Gaming/RGB aesthetics with neon rainbows and particle explosions
- Overly minimal "design-agency reel" style that prioritizes form over substance
- Tutorial screencasts with webcam overlays and casual narration

## Design Principles

1. **Show the code**: Real CUDA snippets and kernel patterns, not abstract diagrams. The audience reads code faster than prose.
2. **Earned confidence**: Every claim is backed by a visible demonstration. No hand-waving, no "imagine if."
3. **Cinematic precision**: Film-grade timing, spring-physics animations, and deliberate pacing. Treat each frame like a shot list.
4. **Developer empathy**: Open with pain the audience has felt. The emotional arc moves from frustration to clarity.
5. **Bilingual parity**: Chinese and English receive equal care in typography, timing, and emphasis. Neither is an afterthought.

## Accessibility & Inclusion

Video content does not require WCAG compliance in the traditional sense, but the following considerations apply: sufficient contrast between text and background (the dark base + light text already handles this), readable code font sizes at 1080p, and subtitle support for both languages. No specific reduced-motion or color-blindness accommodations are required for rendered video output.

## Script Writing Standards

### Narrative Flow
Voiceover scripts should use natural narrative progression between sections, not isolated statements. Each voiceover cue should logically flow from the previous one (e.g., use bridging phrases like "不仅如此" between sections). The pattern for each voiceover cue: general capability → specific mechanism → user benefit.

### Avoid Enumeration in Speech
Do not enumerate specific product names or device models in spoken narration (e.g., don't list "H800, A100, MI300" verbatim). Instead, use collective descriptions like "多种后端执行设备". The visual animation handles showing specific devices — the voiceover provides the conceptual framing.

### User-Provided Text Authority
When the user provides exact Chinese phrasing for voiceover scripts, use it verbatim. Do not paraphrase, rearrange, or "improve" user-provided text. Minor formatting adjustments (spacing, punctuation) are acceptable, but the words themselves must remain unchanged.

### Bilingual Parity in Scripts
Chinese and English voiceover scripts must convey the same information with equal weight. The English version is not a simplified summary — it should carry the same technical precision and emotional tone as the Chinese version.
